Hi Robert,

Great to hear you'll be using the Swagger file to generate your Go client!

Regarding your question about tracking pending invitations - good news! There actually is a dedicated invitation endpoint that should be exactly what you need:

Primary Endpoint for Pending Invitations:

- GET /api/user-invitations - Retrieves all active (non-expired) user invitations for an organization

Additional Invitation-Related Endpoints:

- POST /api/organizations/:id/invite - Create new invitations (single or bulk)

- DELETE /api/user-invitations/:email - Remove a pending invitation

- GET /api/organizations/:id/pending-sso-domains - For SSO domain verification invitations

Key Details:

- The /api/user-invitations endpoint returns all pending invitations that haven't expired (48-hour timeout)

- Requires proper user invitation permissions

- Returns invitation details including email, who created it, and timestamps

- Much cleaner than parsing audit logs!

These endpoints should give you direct access to pending invitation data without needing to experiment with the audit endpoint. The Swagger file should have all the request/response schemas for these endpoints.

Let me know if you have any questions about the invitation endpoints or run into any issues while implementing them in your Go client!
